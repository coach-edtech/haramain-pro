## Coach Clarifications (May 15, 2026)

### Seat License Terminology
- **Seat License** = capacity purchased by Travel Umrah (e.g., 50 seats = 50 Jamaah)
- **Redeem Code** = 6-char alphanumeric code generated by Travel Admin for Jamaah activation
- Flow: Travel buys seat license → Admin generates redeem codes → Jamaah redeems code → seat activated

### Umrah Mandiri Activation Flow
Pure in-app purchase — no Travel involvement:
```
1. User installs app
2. User pays via Xendit in-app purchase (Rp 120.000/lifetime)
3. Payment verified → user auto-Premium
```

### User Roles (Updated)
| Role | Description |
|------|-------------|
| SuperAdmin | Full platform access (Coach Chaidir + designated) |
| Admin HaramainPro | Ops team — Travel config, support settings, NOT license/billing |
| Travel Admin | PPIU owner — manages own travel only |
| Team-Support | Travel staff |
| Muthawif | Group leader |
| Jamaah | End user (via Travel or Mandiri) |
| Jamaah Mandiri | End user (pure self-serve, in-app purchase) |

### Web Architecture
- **Single codebase**: React/Vite + Tailwind
- **Routes**: `/admin/` (SuperAdmin + Admin HaramainPro) + `/travel-admin/` (Travel Admin)
- **Design**: Desktop-centric, mobile-responsive
- **Access Control**: Admin HaramainPro CANNOT access license purchase or billing — only Travel support settings

# SECTION 1: Ringkasan Eksekutif

## 1.1 Overview

Dokumen ini mencakup spesifikasi untuk dua dashboard:

1. **SuperAdmin Dashboard** — Dasbor internal untuk tim operations Haramain Pro untuk mengelola platform secara keseluruhan
2. **Travel Admin Enhancement** — Peningkatan dari TIER 7 dasbor Travel Admin yang sudah ada dengan fitur seat license management, OTA updates, payment gateway, CRM komprehensif, team management, dan sales agent tools

## 1.2 Problem Statement

### SuperAdmin Pain Points:
- Tidak ada visibility terhadap seat license sales dan consumption per Travel
- Billing manual untuk setiap Travel
- Tidak ada sistem monitoring untuk platform health
- User management tersebar tanpa fraud detection

### Travel Admin Pain Points:
- TIER 7 hanya memiliki fitur dasar (Dashboard, Packages, Jamaah, Analytics, Panic Alerts)
- Tidak bisa beli/kelola seat licenses secara self-service
- Tidak ada OTA update management untuk Jamaah
- Tidak ada payment gateway integration
- CRM terbatas, tidak ada lifecycle management lengkap
- Team management masih manual
- Sales agent tools belum ada

## 1.3 Solution

### SuperAdmin Dashboard:
- Centralized seat license tracking dan billing system
- Real-time platform monitoring
- Comprehensive user management dengan fraud detection
- Automated invoice generation

### Travel Admin Enhancement:
- Self-service seat license purchase dan management
- OTA push notification untuk app updates
- Payment gateway integration (Xendit)
- Full pilgrim lifecycle CRM
- Team invitation dan management
- Sales agent code management dan performance tracking

## 2.2 Feature A: Seat License Management (PRIORITY #1)

### 2.2.1 Overview

Seat license system adalah core billing mechanism untuk platform. Setiap Jamaah yang aktif menggunakan app memerlukan satu seat license. Seat license sold = revenue, Seat license consumed = aktiva pax yang benar-benar menggunakan app.

### 2.2.2 User Stories (INVEST Format)

#### US-SA-TOKEN-001: View Seat License Dashboard
```
Story: SuperAdmin wants to see real-time seat license metrics across all Travels
as part of platform operations monitoring

Given: I am logged in as SuperAdmin
When: I navigate to Seat License Management dashboard
Then: I see:
  - Total seat licenses sold (platform-wide)
  - Total seat licenses consumed (active users)
  - Total seat license revenue (Rp)
  - Seat license balance per Travel (table)
  - Low stock alerts (threshold-based)
```

#### US-SA-TOKEN-002: View Seat License Sales Detail
```
Story: SuperAdmin wants to see detailed seat license sales history per Travel
for billing reconciliation

Given: I am logged in as SuperAdmin
And: I selected a specific Travel
When: I click on "Seat License Sales" for that Travel
Then: I see:
  - List of seat license purchases with date, quantity, price
  - Payment status (paid/unpaid/overdue)
  - Invoice link for each purchase
  - Running balance (seat licenses remaining)
```

#### US-SA-TOKEN-003: View Seat License Consumption
```
Story: SuperAdmin wants to track actual seat license usage (active pax)
to calculate true platform engagement

Given: I am logged in as SuperAdmin
And: I am viewing a specific Travel's seat license details
When: I click on "Seat License Consumption"
Then: I see:
  - Number of active pax (logged in within 30 days)
  - Number of consumed seat licenses (unique users)
  - Seat license consumption rate (%)
  - List of active users with last login timestamp
```

#### US-SA-TOKEN-004: Set Low Stock Alert Threshold
```
Story: SuperAdmin wants to configure seat license low-stock alerts per Travel
to prevent service interruption

Given: I am logged in as SuperAdmin
And: I am viewing Travel settings
When: I set low_stock_threshold value (e.g., 50 seat licenses)
Then: System sends alert when Travel seat_balance < threshold
And: Alert appears on dashboard notification panel
```

#### US-SA-TOKEN-005: Generate Invoice Data
```
Story: SuperAdmin wants to generate invoice data per Travel
for billing purposes

Given: I am logged in as SuperAdmin
And: I selected a billing period (month/year)
When: I click "Generate Invoice"
Then: System calculates:
  - Active pax × price_per_seat = total_due
  - Previous payments offset
  - Final invoice amount
And: Invoice PDF is generated and stored
```

### 2.2.3 Data Model

```sql
seat_license_packages
  - id (UUID)
  - travel_id (FK → travels)
  - package_name (e.g., "Paket 100 Seat")
  - quantity (int)
  - price_per_seat (Rp)
  - total_price (Rp)
  - payment_status: enum(pending, paid, overdue)
  - payment_id (FK → payments, nullable)
  - invoice_url (VARCHAR, nullable)
  - created_at
  - paid_at (timestamp, nullable)

seat_license_transactions
  - id (UUID)
  - travel_id (FK → travels)
  - type: enum(purchase, consumed, refunded)
  - quantity (int)
  - related_user_id (FK → users, nullable — for consumed)
  - related_seat_license_package_id (FK → seat_license_packages, nullable)
  - notes (text, nullable)
  - created_at

seat_license_alerts
  - id (UUID)
  - travel_id (FK → travels)
  - threshold (int)
  - is_active (boolean)
  - triggered_at (timestamp)
  - acknowledged_at (timestamp, nullable)
  - acknowledged_by (FK → users, nullable)
```

### 2.2.4 API Endpoints

```
GET    /api/admin/seat-licenses/dashboard
       → Returns: { total_sold, total_consumed, total_revenue, low_stock_travels[] }

GET    /api/admin/seat-licenses/travels/:travel_id
       → Returns: { travel_name, balance, purchases[], consumption[] }

GET    /api/admin/seat-licenses/travels/:travel_id/consumption
       → Returns: { active_pax, consumed_seats, consumption_rate, active_users[] }

POST   /api/admin/seat-licenses/travels/:travel_id/alerts
       Body: { threshold: int }
       → Returns: { alert_id, success: boolean }

POST   /api/admin/seat-licenses/invoices/generate
       Body: { travel_id, billing_period }
       → Returns: { invoice_id, invoice_url }
```

## 3.2 Feature Enhancement A: Seat License Self-Management

### 3.2.1 Overview

Self-service untuk beli, lihat, dan kelola seat licenses. Key flow: Travel Admin beli seat license → generate redeem codes → Jamaah input code → auto-activate (bypass paywall).

### 3.2.2 User Stories (INVEST Format)

#### US-TA-TOKEN-001: View Seat License Balance
```
Story: Travel Admin wants to see current seat license balance
to plan Jamaah onboarding

Given: I am logged in as Travel Admin
When: I navigate to Seat License Management
Then: I see:
  - Current seat license balance (available seats)
  - Total purchased seat licenses
  - Consumed seat licenses (active Jamaah)
  - Seat license usage chart (last 6 months)
```

#### US-TA-TOKEN-002: Purchase Seat License Package
```
Story: Travel Admin wants to purchase seat license packages
to add more seat licenses

Given: I am logged in as Travel Admin
When: I click "Buy Seat Licenses"
Then: I see available packages:
  - 10 seats @ Rp 90rb/seat = Rp 900rb
  - 50 seats @ Rp 80rb/seat = Rp 4jt
  - 100 seats @ Rp 70rb/seat = Rp 7jt
And: I select package and proceed to payment
```

#### US-TA-TOKEN-003: Generate Redeem Codes
```
Story: Travel Admin wants to generate redeem codes for Jamaah
to onboard new pilgrims with pre-paid seats

Given: I am logged in as Travel Admin
And: I have available seat license balance
When: I click "Generate Codes"
Then: System generates codes:
  - Format: 6-char alphanumeric (e.g., "HM7X2K")
  - Each code = 1 seat license consumed
  - I can generate bulk codes (up to seat license balance)
And: Codes displayed with copy button
And: Option to send via WhatsApp/email
```

#### US-TA-TOKEN-004: View Seat License History
```
Story: Travel Admin wants to see who used seat licenses and when
for audit and reconciliation

Given: I am logged in as Travel Admin
When: I click "Seat License History"
Then: I see:
  - List of seat license usage with:
    - Jamaah name
    - Redeem code used
    - Activation date
    - Package/rombongan joined
  - Filter by date range
  - Export to CSV
```

#### US-TA-TOKEN-005: Auto-Deduction Flow
```
Story: System auto-deducts seat license when Jamaah activates redeem code
to maintain accurate seat license balance

Given: Jamaah inputs valid redeem code
When: Code is verified and activated
Then: System:
  - Marks code as used (used_at, used_by_user_id)
  - Decrements travel seat_balance by 1
  - Creates seat_license_transaction record (type: consumed)
  - Links user to travel
```

## 5.3 Database Triggers

```sql
-- Auto-deduct seat license on redeem code activation
CREATE OR REPLACE FUNCTION on_redeem_code_used()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.status = 'used' AND OLD.status = 'available' THEN
    -- Deduct from travel balance
    UPDATE travels SET seat_balance = seat_balance - 1 WHERE id = NEW.travel_id;
    
    -- Record transaction
    INSERT INTO seat_license_transactions (travel_id, type, quantity, related_user_id, related_seat_license_package_id)
    VALUES (NEW.travel_id, 'consumed', 1, NEW.used_by_user_id, NEW.id);
    
    -- Check low stock alert
    PERFORM check_low_stock_alert(NEW.travel_id);
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_redeem_code_used
AFTER UPDATE ON redeem_codes
FOR EACH ROW EXECUTE FUNCTION on_redeem_code_used();

-- Auto-activate Premium on mandiri subscription payment
CREATE OR REPLACE FUNCTION on_mandiri_payment_success()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.payment_status = 'success' AND NEW.type = 'mandiri_subscription' THEN
    -- Update user to Premium
    UPDATE profiles SET subscription_status = 'premium', subscription_expires_at = NOW() + INTERVAL '100 years'
    WHERE id = (SELECT user_id FROM payments WHERE id = NEW.id);
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_mandiri_payment_success
AFTER UPDATE ON payments
FOR EACH ROW EXECUTE FUNCTION on_mandiri_payment_success();

-- Log user activity on login
CREATE OR REPLACE FUNCTION on_user_login()
RETURNS TRIGGER AS $$
BEGIN
  UPDATE users SET last_login_at = NOW() WHERE id = NEW.id;
  INSERT INTO user_activity_log (user_id, event_type, event_data)
  VALUES (NEW.id, 'login', jsonb_build_object('timestamp', NOW()));
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_user_login
AFTER INSERT ON user_activity_log
FOR EACH ROW WHEN (NEW.event_type = 'login')
EXECUTE FUNCTION on_user_login();

-- Low stock alert check function
CREATE OR REPLACE FUNCTION check_low_stock_alert(travelId UUID)
RETURNS VOID AS $$
DECLARE
  threshold INTEGER;
  current_balance INTEGER;
  alert_exists BOOLEAN;
BEGIN
  SELECT threshold INTO threshold FROM seat_license_alerts 
  WHERE travel_id = travelId AND is_active = true;
  
  IF threshold IS NOT NULL THEN
    SELECT seat_balance INTO current_balance FROM travels WHERE id = travelId;
    
    IF current_balance < threshold THEN
      SELECT EXISTS(SELECT 1 FROM seat_license_alerts 
        WHERE travel_id = travelId AND is_active = true AND triggered_at IS NULL)
      INTO alert_exists;
      
      IF alert_exists THEN
        UPDATE seat_license_alerts SET triggered_at = NOW() 
        WHERE travel_id = travelId AND is_active = true AND triggered_at IS NULL;
      END IF;
    END IF;
  END IF;
END;
$$ LANGUAGE plpgsql;
```

# SECTION 6: Security & Permissions

## 6.1 Row Level Security (RLS)

```sql
-- SuperAdmin: Full access to all travels
ALTER TABLE travels ENABLE ROW LEVEL SECURITY;
ALTER TABLE seat_license_transactions ENABLE ROW LEVEL SECURITY;
ALTER TABLE invoices ENABLE ROW LEVEL SECURITY;

-- Users can only see their own data
ALTER TABLE users ENABLE ROW LEVEL SECURITY;

-- Travel Admin: Access only to their own travel
-- (Implemented via travel_id foreign key and RLS policies)

-- Row Level Security Policies
CREATE POLICY "SuperAdmin can view all travels" ON travels
  FOR SELECT TO authenticated
  USING (auth.jwt() ->> 'role' = 'super_admin');

CREATE POLICY "TravelAdmin can view own travel" ON travels
  FOR SELECT TO authenticated
  USING (
    auth.jwt() ->> 'role' = 'travel_admin' 
    AND id = (auth.jwt() ->> 'travel_id')::uuid
  );

CREATE POLICY "Users can view own profile" ON profiles
  FOR SELECT TO authenticated
  USING (id = auth.uid());

CREATE POLICY "TravelAdmin can manage own invitation codes" ON invitation_codes
  FOR ALL TO authenticated
  USING (
    auth.jwt() ->> 'role' = 'travel_admin'
    AND travel_id = (auth.jwt() ->> 'travel_id')::uuid
  );
```
